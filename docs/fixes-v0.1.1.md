# v0.1.1 出场与离婚修复

## 修复针对的问题

用户最新进度包含三条已婚记录，但同一对象在运行时存在两份角色实例，只有其中一份被关系记录关联。旧实现只扩展召唤调用，没有核对注册表中的实际实例；一位主对象失败时还会跳过其余对象。原版有些空动作返回 0，旧日志也可能误把请求接受当作已完成出场。

离婚另有两个问题：公共伴侣偏好会影响离婚查询；原版删除数组元素时可能用末项填补空位，离婚入口之后仍读取原位置来发送通知，可能通知另一位对象。

## 当前实现

- 从原版调用关系和指令中解析角色注册表、创建入口、所属玩家字段及离婚入口，不写死本机 RVA。
- 只处理当前玩家、当前可操作角色和真实已婚 NPC 保存键对应的实例。场景里的普通 NPC、其他角色的伴侣不加入处理集合。
- 原生创建入口先检查实例，复用已有实例并返回其真实 ActorId，缺少时才执行原版创建。已有副本在下一次全员召唤 / 收回时，通过原版动作逐个收回。
- 运行时实例 DWORD 关联通过重新查找记录后进行原子更新；不修改对象键、婚姻状态或存档格式。复用时仍经过原版控制器发送召唤回执，避免只改一侧关联。
- 原版返回 0 但关联没有解除时，不能记作已收回。异步收回实例按 ActorId、地址和所属对象追踪，退出注册表前不再复用或重新生成。
- 一位对象失败仍会处理其余对象；每位对象都保留原版场景检查。日志分别记录原生结果、实例数量、待完成移除及核验结果。
- 无编号旧入口只接受确认交互步骤中经过核验的玩家 / NPC 两端，两端顺序均支持；两端都不是当前玩家时忽略。预占和对话缓存不作为目标。离婚时再次验证对象仍存在且属于当前角色的已婚记录；交互重置、对话结束、失败或无效玩家请求会清除上下文。
- 正常按编号路径保留原生显式目标，先处理该对象的副本，再由原版完成离婚，不借用全局展示偏好。
- 离婚不使用最近新婚 / 手动展示偏好；查询返回本次真实记录的独立只读快照，防止数组删除换位后通知其他对象。
- 离婚前只额外收回同一对象的重复实例，正在对话的那份保留给原版离婚处理，避免普通收回的“对话中不可收回”限制阻止合法离婚。

五项条件覆盖仍独立安装。其后的 9 个原生入口要求成套安装，防止对象偏好在缺少离婚保护时生效。布局或请求处理方法不兼容时，日志输出 `COMMIT HOOK UNAVAILABLE`。

## 使用与验证

1. 完整退出游戏，更新 `.asi`，保留原来的 INI；日志首行应显示 `v0.1.1`。
2. 保持 `Enabled=1`。修复创建去重和离婚目标选择不需要新增开关，检查 `RelationshipGuardsActive=1`。
3. 需要处理全员出场时，保持 `SpawnAllPartners=1` 和 `SpawnAllActive=1`。婚礼结束、退出 NPC 对话后，触发一次原版收回 / 召唤。
4. 检查各对象 `PARTNER INSTANCE`：稳定后召唤应为 `after=1 verified=1`，收回应为 `after=0 verified=1`。`pending=1` 仍需等待原版移除完成；核验注册表不等于已完成所有渲染、位置和跟随行为。
5. 分别进入两位伴侣的交互，确认 `INTERACTION TARGET` 随实际对象改变。更新或读档后要重新进入交互，不使用上次进度的目标。
6. 在存档副本上执行一次离婚后，用 `DIVORCE REQUEST` / `DIVORCE RESULT`（按编号路径）或 `DIVORCE TARGET`（旧入口）核对操作对象，再检查新存档仅移除目标关系，其他伴侣保留。

目标不明确时会出现 `DIVORCE BLOCKED` 并停止操作，不会回退到第一位或最近的新婚对象。若捕获不到交互请求或原版场景阻止收回副本，应保留日志继续定位。

## 验证边界

当前已完成本机 EXE 的自动定位、私有映像挂钩安装 / 撤回，以及含真实注册表布局的离线模型验证。模型覆盖两位出场、缺失实例、重复实例、异步移除、主失败、角色隔离、无效请求，以及指定 A 时偏好为 B、A 是重复实例、原版数组发生换位的离婚流程。

运行中已核验三位各自收回并重新生成一份实例。20:20 的 slot108 从三条已婚变为两条，仅移除 1176，保留 1178 / 1179；用户确认离婚对象就是点击的对象，另外两位关系仍在。这次走正常按编号路径；无编号旧入口的目标 / 快照保护仍以模型验证为主，不能把它当作所有 NPC 和路径都已实机覆盖。

随后重新加载两位伴侣的 slot108，原版入口生成两位各一份，日志 `verified=2 pending=0`，只读快照确认每位一个实例且关联正确；用户确认画面中看到两人。日志还在原版拒绝收回 / 空动作时重新读取实例数，避免把未采集的默认 0 误认为角色已经消失。

没有新增后台生成线程、直接释放角色对象或直接改写婚姻存档的逻辑。位置、跟随、剧情与完整多人婚礼等仍需验证。
